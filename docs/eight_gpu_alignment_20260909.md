# 八卡 BS64 与单卡、BS32 的对齐审查

日期：2026-09-09。未启动、停止或重启任何 GPU 训练。

## 用户确认的配置语义

- 单机八卡，每次前向全局模型条件样本数64，每卡8。
- 坐标微批1500，梯度累计2次；正常更新覆盖64个模型条件样本 × 3000次坐标采样。
- “模型条件样本”是速度/频率/震源组合，不保证是64个不同的基础速度模型。
- 坐标累计不会把64个条件样本变成128个条件样本。之前将模型BS乘累计次数称为有效模型BS并不准确。
- 各rank使用相同的坐标批，分割的是模型条件样本轴；不将1500再除以8。
- Halton保持现有取整实现和50%比例；完整PML指不裁切计算域，不等于遍历全部网格点。

## 本次修复

1. 普通/分阶段DDP共用单卡的 `coordinate_accumulation_batches`：按实际点数加权，最后一组完成同步更新，在模型批次边界结束累计。
2. 两条DDP路径的训练、验证、baseline统计按模型-坐标对数量加权。各rank训练样本数与坐标数相同，因此rank均值的平均等于全局按点平均。
3. 每个累计组最后一个反向传播触发实数参数的原生DDP平均，其他微批使用 `no_sync()`；不额外除以8，也不重复除以累计次数。
4. 修复复数FNO通信兼容性。当前torch2.6+CPU/Gloo上，原生DDP构造含复数参数模型会报 `RuntimeError: Invalid scalar type`。复数参数保留原存储、运算和checkpoint键，从原生DDP reducer中排除；初始化通过实部/虚部视图广播，每组末尾通过实部/虚部梯度桶做全局平均。实数参数仍由原生DDP管理。完整模型与Adam均继续使用原复数参数。
5. 复数同步检查所有rank的梯度是否存在，避免某一rank遗漏参数后静默不同步。

当前严格DDP仍仅允许Data+PDE、FNO分支、无y_ran、无连续频率辅助PDE、无FiLM正则；不会关闭主FiLM的空间导数。

## 单卡BS64与八卡8×8的等价条件

每rank计算局部平均梯度g_r；DDP得到sum(g_r)/8，等于同一组64个条件样本的全局平均梯度。
成立条件：相同初始权重、优化器状态、normalizer、学习率、模型条件样本集合、坐标及累计组边界；没有跨样本BatchNorm或未对齐随机层。

这不是声称两个默认入口的整条训练轨迹逐位一致：

- 默认单卡RandomSampler和DDP DistributedSampler的种子/排列机制不同。
- DDP每epoch重置坐标generator，单卡当前连续推进generator；实际坐标分组序列不同。
- 新训练normalizer仍来自首个训练epoch的更新过程中均值；只修复其点数权重，未改变baseline估计时机。因此不同采样顺序可能带来不同normalizer。
- 初始权重需显式使用同一快照，不能只假定两个启动入口构造的权重相同。
- 浮点归约顺序不同允许小舍入差异，不保证GPU数值逐位一致。

若要逐步对照：使用同一初始化/optimizer快照、固定同一baseline，明确给定相同全局模型索引和坐标批。下述八进程测试使用这个控制方案，而非比较两个随机训练日志。

## 测试证据及局限

- CPU/Gloo八进程，每rank BS8，对照单进程BS64；真实生产 `compute_loss` / PDE算子，小FiLM网络加真实SpectralConv2d复数参数。
- 160×180完整PML；坐标微批包括1500、900、375，覆盖等长、非等长和未满累计组。
- 对比Data/PDE/total loss、所有实数/复数梯度、三次Adam更新：通过。
- 最大梯度绝对差8.94069672e-8；三次更新观察到的最大参数绝对差0（该测试，不是普遍逐位等价保证）。
- 完整Pi_DeepONet在CPU/Gloo上两次小样本Adam更新通过；检查所有可训练参数梯度存在、有限，checkpoint键不变。
- 没有进行八张物理GPU/NCCL测试，没有测量八卡吞吐、显存峰值或互联带宽；小模型八进程测试不能替代完整模型NCCL上线测试。

## BS64与BS32：7200训练条件样本、完整PML的计数

160×180×50%=14400次Halton采样；坐标微批9×1500+900=10批；累计2次，每个模型批更新5次。

| 指标 | 全局BS32 | 全局BS64 |
|---|---:|---:|
| 每次普通更新的条件样本数 | 32 | 64 |
| 每次普通更新模型-坐标对 | 96000 | 192000 |
| 最后一个坐标累计组模型-坐标对 | 76800 | 153600 |
| 每epoch模型批数（drop_last=True） | 225 | 112 |
| 每epoch使用的条件样本数 | 7200 | 7168 |
| 每epoch丢弃的条件样本数 | 0 | 32 |
| 每epoch优化器更新数 | 1125 | 560 |
| 1000个完整训练epoch的更新数 | 1125000 | 560000 |

注：配置NIter=1001实际训练epoch0..1000，共1001轮，不等于表中1000轮。若改用全部28800网格点而非50%Halton，每个模型批20坐标微批、10次更新，上表更新数翻倍。

因此BS64不是BS32的相同训练轨迹：同样epoch数，模型见到的数据总量接近，但Adam更新次数约减半。坐标不裁切本身也会改变PDE采样区域，不应与BS效应混在同一对照中。

如果模型条件样本梯度独立同分布，BS翻倍使该部分梯度方差约减半、标准差约乘0.707；这里含相同基础速度的不同频率/震源，且各rank共享坐标，因此不能把该近似当作实际总梯度噪声或最终误差的测量。

学习率保持原值，不自动乘8或乘2。按epoch运行的warmup/余弦调度，在BS64下每段经历约一半更新；没有代码故障，但“相同数据遍历次数”和“相同优化器更新次数”是两种不同实验预算。不能凭BS推算最终validation差多少或保证收敛相同。

## 后续上线条件

- 当前入口是单机多卡mp.spawn，不支持直接跨两台机器的4+4；跨机需另行改造启动与数据路径。
- 先在目标八卡机器上做完整模型、相同初始化/固定normalizer的短程NCCL冒烟测试，再正式长跑。
- 八rank会分别准备数据集，主机内存和数据读取压力需要实际检查。
- 复数梯度同步目前在反向传播末尾发生，会增加通信时间；不改变梯度含义，尚未做通信/计算重叠优化。
- 正式训练配置没有在本次修改中切换；运行中的进程仍使用启动时加载的代码。
